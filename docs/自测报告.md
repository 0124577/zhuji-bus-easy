## 三、关键场景说明

### 3.1 实时公交（车辆位置 / 剩余站 / 预计到站）

- 使用官方真实接口验证：`火车站` 站点页在测试时段返回 **30 个方向有车**，逐条渲染车牌、位置文案、剩余站与分钟。
- 使用定向 mock 验证确定性分支：等车站为线路第 11 站、车辆 `vehicleOrder=10`、`isArriveStation=0` 时，页面大字显示 **1 站**，副标题 `约 3 分钟 · 520 米`，时间轴车辆图标落在第 10 站与第 11 站之间。
- 站序口径按官方定义处理：`vehicleOrder` 为「已驶离站」，剩余站数 = 目标站序号 − `vehicleOrder`；`vehicleOrder == 目标站` 且未停靠时视为刚离站，不计入。

### 3.2 本地到站提醒

- 设置「下一站提醒」后写入 `localStorage`，等车站条显示「提醒中」。
- 轮询到车辆剩 1 站时：弹窗出现（标题「车辆即将到站」，含车牌、站名、方向），同时调用 `navigator.vibrate([400,150,400,150,700])`（测试中替换 `navigator.vibrate` 计数为 1 次）。
- 触发后提醒标记 `done`，首页卡片显示「已提醒 19:03」，管理弹层可删除。
- 全程无 Notification / Service Worker / 推送 SDK 调用，符合「不做推送」约束。

### 3.3 边界与降级

| 场景 | 表现 |
|---|---|
| 网络异常（车辆/详情/时刻表接口全部抛错） | 数据卡显示「实时车辆暂不可用」+ 错误原因 + 重新获取；站点序列、首末班、收藏、换乘照常可用；页脚注明「当前显示静态站点数据」 |
| 定位被拒绝 | 附近站点卡片显示「定位失败，可能是权限未开启」+ 重新定位按钮；顶部胶囊「定位失败」；线路搜索不受影响 |
| 站点搜索无结果 | 弹层显示「没有找到包含「…」的站点，换一个关键词试试」 |
| 线路搜索无结果 | 线路区显示「没有找到「…」相关线路」 |
| 起终点相同 | 点击查询提示「起点和终点不能是同一个站点」，不生成方案 |
| 收班时段 | 数据卡显示「已收班 / 当前时段已收班（06:20–17:50）」，若已取到时刻表则给出下一班计划发车与预计到站，标注「静态时刻表估算」 |

### 3.4 移动端适配

- 390×844 下 首页、去哪、线路页、站点页 `scrollWidth ≤ innerWidth`，无横向滚动。
- 长站名在时间轴竖排最多 8 字后省略；站点列表单行省略；车牌/位置文案单行省略，不挤压右侧时间。
- 底部 Tab 固定，含 `safe-area-inset-bottom`；全屏页与弹层使用历史栈，安卓返回键先关弹层再关页面。

## 五、复现方式

```bash
# 1. 启动静态站点
python -m http.server 8899 --directory www

# 2. 运行 E2E（需本地 Chrome，可用 CHROME_PATH 指定）
node tests/e2e/app-test.mjs

# 3. 重新生成静态数据（可选）
python scripts/extract-data.py

# 4. 重新打包 APK
npx cap sync android
cd android && ./gradlew assembleRelease
```

## 六、遗留与说明

1. 官方实时接口在夜间收班后返回空车辆列表，属数据真实状态，页面按「已收班」呈现，不使用假数据填充。
2. 提醒为前台轮询（15 秒），App 退到后台或锁屏不触发；这是「本地提醒、不做推送」的取舍。
3. 无地图渲染，附近站点距离为直线距离，换乘耗时为静态里程估算。
4. 静态快照需随官方线路调整重新生成（`scripts/extract-data.py` 依赖 v2.0.0 基线 `index.html`）。
5. 部分线路官方时刻表接口返回空数组，此时仅展示首末班与实时车辆。
