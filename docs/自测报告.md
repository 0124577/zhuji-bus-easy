## 三、关键场景说明

### 3.1 换乘方案详情页（本版核心，对照参考图 5、6）

- 在「去哪」输入起终点生成方案后，方案卡片底部提示「查看分段实时公交与到站提醒」，整卡可点（`data-act="plan-open"`），索引切换按钮 `plan-idx` 阻断冒泡，不会误跳。
- **顶部实时高亮条（本版新增）**：进入详情页第一眼就是「还有 **N** 站到上车站」——粉底白字、35px 数字、左侧独立分栏；右侧给出「约 X 分钟到站 · 「上车站名」」与「线路 · 第几段 · 车牌」；点击高亮条平滑滚到对应乘车段。无在线车辆时不渲染该条，改用「暂无在线车辆 / 静态数据」口径。
- 详情页顶部汇总：总耗时大字、预计到达时间、共 N 站 / M 段、状态标签（`实时更新中` / `暂无在线车辆` / `静态数据`）。
- 每一乘车段独立查询该方向实时车辆（并发 3 个请求，20 秒轮询），并按 `dirId` 缓存 `{vehicles, err, at}`；某段失败不影响其它段。
- 分段卡片内容：线路徽标与方向、上车站→下车站、实时块（**白字粉底胶囊「还有 N 站」26px 数字** + 约 X 分钟 + 车牌 + 位置文案，失败时橙色「实时数据不可用」+ 重新获取）、横向站点条（自动居中上车站）、竖向大字时间轴（标记上/下车）、「打开线路实时页」跳转。
- 单段实时数据的口径与线路页一致：`vehicleOrder` 为「已驶离站」，剩余站数 = 目标站序号 − `vehicleOrder`；目标站与车辆同站且未停靠时视为刚离站。

### 3.2 老年友好竖向时间轴

- 位置：横向时间轴正下方，标题「竖向时间轴 · 大字」，右侧提示「点铃铛开关提醒」。
- 度量（E2E 断言实测值）：站名 ≥15px（详情页 ≥16px）、行高 ≥56px、轴线宽 3px 且连续、铃铛按钮 40×40px（详情页 ≥38px）。
- 每行结构：轴线圆点 + 站名 + 序号 + 「还有 N 站 · 约 X 分钟」+ 车辆徽标（`停靠本站` / `正在本站 → 下一站`）+ 铃铛。
- 车辆已过站时显示「车辆已过站」并灰化，不再显示分秒倒计时；本站已有车辆时不再重复显示分钟数，避免同一信息出现两次。

### 3.3 站点级提醒开关

- 线路页与方案详情页共用同一弹层 `ZJ.Reminder.openSheet`，`rm-mode` / `rm-save` / `rm-cancel` 只在 `reminder.js` 注册一次，避免重复绑定导致的重复触发。
- 开启后铃铛高亮（`.pl-bell.on`），提醒写入 `localStorage`（`zjbus.reminders.v1`），首页提醒卡片同步出现；关闭后铃铛取消高亮、记录清空。
- 触发逻辑与 v1.0.0 一致：剩 1 站时弹窗 + `navigator.vibrate([400,150,400,150,700])`，全程无 Notification / Service Worker / 推送 SDK。

### 3.4 横屏→竖屏的站点浏览方式

- 站点列表改为竖屏横向滚动：`.tl-scroll{overflow-x:auto}`，内容宽 > 可视宽，可滚动到第 38 站；站名竖排（`writing-mode: vertical-rl`），已过站灰化、当前站高亮、车辆图标置于线路条上方。
- 进入页面自动把焦点站（等车站/上车站）滚到可视区中间；用户滑动后提示文案变为「共 N 站 · 左右滑动浏览全程」。
- 轮询刷新时保持滚动位置（`opt.restore`），不会因重绘跳回起点。

### 3.5 边界与降级

| 场景 | 表现 |
|---|---|
| 实时接口连续 2 次失败 | `ZJ.Api.degraded = true`；线路页顶部 `#lineBanner`、详情页顶部 `.degrade-banner` 显示「实时数据已自动降级为静态数据」，附重试按钮；静态站序、首末班、收藏、换乘、站点提醒照常可用 |
| 单段接口失败（详情页） | 该段显示橙色「实时数据不可用」+ 重新获取，其余段正常；汇总标签转为「静态数据」 |
| 网络异常（全部接口抛错） | 数据卡显示「实时车辆暂不可用」+ 错误原因 + 重新获取；页脚注明「当前显示静态站点数据」 |
| 定位被拒绝 | 首页正常渲染，`ZJ.Geo.state === 'fail'`，不再有附近站点模块残留，无横向溢出；去哪「我的位置」提示不可用 |
| 站点搜索无结果 | 弹层显示「没有找到包含「…」的站点，换一个关键词试试」 |
| 线路搜索无结果 | 线路区显示「没有找到「…」相关线路」 |
| 无直达线路 | 给出换乘方案；确实无方案时给出空态提示 |
| 起终点相同 | 提示「起点和终点不能是同一个站点」，不生成方案 |
| 收班时段 | 数据卡「已收班 / 当前时段已收班（06:20–17:50）」，若已取到时刻表则给出下一班计划发车与预计到站，标注「静态时刻表估算」 |
| 安卓返回键 | 详情页优先响应 `popstate` 关闭，返回后仍停留在「去哪」页，Tab 状态不丢 |

## 七、遗留与说明

1. 官方实时接口在夜间收班后返回空车辆列表，属数据真实状态，页面按「已收班」/「暂无在线车辆」呈现，不使用假数据填充。
2. 提醒为前台轮询（线路页 15 秒、方案详情页 20 秒），App 退到后台或锁屏不触发；这是「本地提醒、不做推送」的取舍。
3. 无地图渲染，换乘耗时为静态里程估算，并非路况实时耗时。
4. 静态快照需随官方线路调整重新生成（`scripts/extract-data.py` 依赖 v2.0.0 基线 `index.html`）。
5. 部分线路官方时刻表接口返回空数组，此时仅展示首末班与实时车辆。
6. 方案详情页对每段并发 3 个请求，跨 2 段以上的长链路在弱网下首屏会略慢，已有分段骨架占位与失败重试。
